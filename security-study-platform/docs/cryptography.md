# 🔐 암호학(Cryptography) — 정보보안기사·실무·면접 완전정리

> 목표: 정보보안기사에서 자주 출제되는 암호학 핵심을 대칭키·공개키·해시·MAC·전자서명·PKI·키 관리까지 하나의 흐름으로 이해하고, 실기 서술형·TLS·인증서·VPN·기술면접까지 연결한다.

## 1. 암호학의 핵심 목적

| 보안 목표 | 의미 | 대표 기술 |
|---|---|---|
| 기밀성(Confidentiality) | 허가받지 않은 사용자가 내용을 읽지 못하도록 보호 | 암호화 |
| 무결성(Integrity) | 데이터가 변경·변조되지 않았음을 확인 | Hash, MAC |
| 인증(Authentication) | 사용자·시스템·메시지의 진위를 확인 | MAC, 전자서명, 인증서 |
| 부인방지(Non-repudiation) | 송신자가 자신의 행위를 나중에 부인하지 못하도록 함 | 전자서명 |

암호 시스템의 안전성은 알고리즘을 숨기는 것보다 **키를 안전하게 관리하는 것**에 기반해야 한다. 이는 Kerckhoffs의 원리와 연결해 기억한다.

## 2. 대칭키 암호

대칭키 암호는 암호화와 복호화에 동일한 공유 비밀키를 사용한다.

| 알고리즘 | 특징 | 시험 포인트 |
|---|---|---|
| DES | 64bit 블록, 유효 키 56bit | 현재는 키 길이가 짧아 안전하지 않음 |
| 3DES | DES 반복 적용 | 레거시 방식 |
| AES | 128bit 블록 | 128/192/256bit 키 |
| SEED | 국내 개발 블록 암호 | 128bit 블록 |
| ARIA | 국내 개발 블록 암호 | 128bit 블록, 128/192/256bit 키 |
| RC4 | 스트림 암호 | 현대 보안 프로토콜에서는 사용 권장되지 않음 |

### AES 핵심

| 종류 | 키 길이 | Round |
|---|---:|---:|
| AES-128 | 128bit | 10 |
| AES-192 | 192bit | 12 |
| AES-256 | 256bit | 14 |

AES 기본 Round 연산은 `SubBytes → ShiftRows → MixColumns → AddRoundKey`이며, **마지막 Round에서는 MixColumns를 수행하지 않는다.**

## 3. 블록 암호와 스트림 암호

- 블록 암호: AES, DES/3DES, SEED, ARIA
- 스트림 암호: 비트 또는 바이트 단위 Key Stream과 평문을 결합. 대표적으로 RC4
- 스트림 암호의 기본 형태: `Plaintext XOR Key Stream = Ciphertext`

## 4. 블록 암호 운영 모드

| 모드 | 특징 | 핵심 포인트 |
|---|---|---|
| ECB | 각 블록 독립 암호화 | 동일 평문 블록 → 동일 암호문 블록, 패턴 노출 |
| CBC | 현재 평문과 이전 암호문을 XOR 후 암호화 | 첫 블록에 IV 필요 |
| CFB | 블록 암호를 스트림 형태로 사용 | Feedback 방식 |
| OFB | 암호 출력값을 다시 입력으로 사용 | 오류 전파 특성 구분 |
| CTR | Counter 값을 암호화해 Key Stream 생성 | 병렬 처리 가능 |

CBC 첫 블록 예시: `P1 XOR IV → E(K) → C1`

**빈출:** CBC에서 첫 번째 평문 블록을 암호화할 때 필요한 값은 **IV(Initialization Vector)**.

## 5. 공개키 암호

공개키 암호는 공개키와 개인키를 사용한다. 공개키는 배포 가능하지만 개인키는 소유자가 안전하게 보호해야 한다.

| 알고리즘 | 주요 용도 | 기반 문제 |
|---|---|---|
| RSA | 암호화, 전자서명 | 큰 정수 소인수분해의 어려움 |
| Diffie-Hellman | 키 합의 | 이산로그 문제 |
| ECC | 키 합의·전자서명 계열 | 타원곡선 이산로그 문제 |
| ElGamal | 공개키 암호 | 이산로그 문제 |
| DSA | 전자서명 | 이산로그 문제 |

## 6. RSA

RSA 기본 계산 순서:

1. 서로 다른 소수 `p`, `q` 선택
2. `n = p × q`
3. `φ(n) = (p-1)(q-1)`
4. `gcd(e, φ(n)) = 1`인 `e` 선택
5. `e × d ≡ 1 (mod φ(n))`을 만족하는 `d` 계산

- 공개키: `(e, n)`
- 개인키: `(d, n)`
- 암호화: `C = M^e mod n`
- 복호화: `M = C^d mod n`

시험에서는 `p·q → n → φ(n) → e → d → 암호화/복호화` 순서를 반복 연습한다.

## 7. Diffie-Hellman

Diffie-Hellman의 목적은 데이터 암호화 자체가 아니라 **공유 비밀값 합의**다. 기본 Diffie-Hellman은 상대방 인증을 자체 제공하지 않으므로 **MITM(중간자 공격)** 위험이 있다. 실제 환경에서는 인증서나 전자서명과 결합한다.

- Diffie-Hellman = 키 합의
- RSA = 공개키 기반 암호화·서명에 활용 가능

## 8. 대칭키와 공개키 비교

| 구분 | 대칭키 | 공개키 |
|---|---|---|
| 키 | 동일한 공유키 | 공개키 + 개인키 |
| 속도 | 빠름 | 상대적으로 느림 |
| 대용량 데이터 | 적합 | 비효율적 |
| 키 배포 | 안전한 공유가 어려움 | 공개키 배포 가능 |
| 대표 | AES, SEED, ARIA | RSA, ECC |
| 주요 역할 | 실제 데이터 암호화 | 키 합의·키 전달·인증·서명 |

TLS 같은 실제 프로토콜은 공개키/키 합의 방식으로 세션 비밀을 설정하고, 대칭키로 실제 애플리케이션 데이터를 보호하는 **하이브리드 방식**을 사용한다.

## 9. 해시 함수

해시 함수는 임의 길이 입력을 일정 길이의 Message Digest로 변환한다. 일반적인 암호화와 달리 원문 복원을 위한 복호화 절차를 목적으로 하지 않는다.

| 알고리즘 | Digest 길이 | 상태 |
|---|---:|---|
| MD5 | 128bit | 충돌 취약, 보안 목적 사용 금지 수준 |
| SHA-1 | 160bit | 충돌 취약, 신규 보안 용도 사용 지양 |
| SHA-256 | 256bit | SHA-2 계열 |
| SHA-512 | 512bit | SHA-2 계열 |

### 해시 공격

- 역상 공격(Preimage): 주어진 해시값에 대응하는 원문 찾기
- 제2역상 공격(Second Preimage): 주어진 `M1`과 같은 해시를 만드는 다른 `M2` 찾기
- 충돌 공격(Collision): 서로 다른 `M1`, `M2`에 대해 `H(M1) = H(M2)` 찾기
- 이상적인 n비트 해시의 충돌 공격 복잡도는 Birthday Paradox에 의해 대략 `2^(n/2)`

## 10. MAC과 HMAC

MAC(Message Authentication Code)은 메시지와 비밀키를 이용해 **무결성 + 메시지 인증**을 제공한다.

- HMAC = 해시 함수 + 비밀키 기반 MAC
- 공유 비밀키를 사용하는 MAC은 전자서명과 같은 의미의 부인방지를 제공하지 않는다.

## 11. 전자서명

전자서명 기본 흐름:

1. 송신자가 메시지를 해시한다.
2. 생성된 해시값에 송신자의 개인키로 서명한다.
3. 수신자는 송신자의 공개키로 서명을 검증한다.
4. 메시지를 다시 해시해 검증 결과와 비교한다.

핵심 암기:

- **기밀성을 위한 암호화:** 수신자 공개키로 암호화 → 수신자 개인키로 복호화
- **전자서명:** 송신자 개인키로 서명 → 송신자 공개키로 검증

전자서명은 주로 **인증 + 무결성 + 부인방지**를 제공한다.

## 12. PKI와 인증서

PKI(Public Key Infrastructure)는 공개키를 신뢰할 수 있게 배포·검증하기 위한 체계다.

| 구성요소 | 역할 |
|---|---|
| CA | 인증서 발급·서명 |
| RA | 인증서 신청자의 신원 확인·등록 지원 |
| X.509 인증서 | 주체의 신원 정보와 공개키를 연결 |
| CRL | 폐기된 인증서 목록 |
| OCSP | 인증서 상태를 온라인으로 확인 |

인증서에는 일반적으로 주체, 공개키, 발급자, 유효기간, 일련번호, 서명 알고리즘, CA 전자서명 등이 포함된다.

## 13. Salt와 비밀번호 저장

단순한 `Hash(password)` 대신 사용자마다 고유한 Salt를 사용하면 동일한 비밀번호가 동일한 저장값으로 나타나는 것을 방지하고 Rainbow Table 같은 사전 계산 공격을 어렵게 한다.

비밀번호 저장에는 일반 SHA-256 단독 사용보다 **PBKDF2, bcrypt, scrypt, Argon2** 같은 비밀번호 해싱/KDF 방식을 사용한다.

## 14. 대표 암호 공격 모델

| 공격 | 공격자가 가진 정보/능력 |
|---|---|
| COA | 암호문만 알고 있음 |
| KPA | 일부 평문과 대응 암호문을 알고 있음 |
| CPA | 원하는 평문을 선택해 암호문 획득 가능 |
| CCA | 원하는 암호문을 선택해 복호화 결과 획득 가능 |

## 15. One-Time Pad

완전한 비밀성(Perfect Secrecy)을 제공하려면 키가 다음 조건을 만족해야 한다.

- 평문과 같은 길이
- 완전히 무작위
- 한 번만 사용
- 안전하게 공유·보관

이론적으로 강력하지만 키 배포·보관이 매우 어렵다.

## 16. 정보보안기사 핵심 암기표

- AES → 대칭키 / 블록 암호 / 128bit 블록
- RSA → 공개키 / 소인수분해 문제
- Diffie-Hellman → 키 합의
- ECC → 타원곡선 이산로그 문제 기반
- Hash → 무결성 확인의 핵심 기반 기술
- HMAC → 무결성 + 메시지 인증
- 전자서명 → 인증 + 무결성 + 부인방지
- PKI → 공개키 인증 체계
- CA → 인증서 발급
- RA → 신원 확인·등록 지원
- CRL → 인증서 폐기 목록
- OCSP → 인증서 상태 확인
- X.509 → 공개키 인증서 표준
- Salt → 비밀번호 사전 계산 공격 방어에 도움
- CBC → 첫 블록에 IV 필요
- ECB → 동일 평문 블록의 패턴 노출 위험

## 17. 실기 답안 작성 틀

암호학 실기 서술형은 다음 구조로 작성한다.

1. **정의** — 무엇인가
2. **목적** — 어떤 보안 서비스를 제공하는가
3. **원리** — 키·해시·서명 흐름은 어떻게 되는가
4. **취약점/주의점** — 어떤 공격에 취약한가
5. **대응** — 안전한 알고리즘·키 길이·키 관리·인증 절차는 무엇인가
6. **실무 연결** — TLS, VPN, 인증서, 비밀번호 저장에서 어떻게 쓰이는가
